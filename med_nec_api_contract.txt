MEDICAL NECESSITY API - REQUEST AND RESPONSE
============================================


MARKING A PAYLOAD AS PREVIOUSLY CHECKED
---------------------------------------

Add these two fields to the payload:

    "clarifyingQuestion": "the question we returned on the first call",
    "clarifyingAnswer": "what the requester typed in response"

Both populated means we treat it as a recheck. Send the rest of the
payload unchanged.

If you would rather keep it on a separate route,
POST /v1/medical-necessity/reevaluate does the same thing:

    {
      "tripRequest": { "...the original payload, unchanged..." },
      "clarification": {
        "question": "the question we returned",
        "answer": "what the requester typed"
      }
    }

FIELDS FOR THE UI
-----------------

  meetsMedicalNecessity   boolean           true or false

  clinicalSummary         string            Display text, two sentences

  clarifyingQuestion      string or null    NULL MEANS SHOW NOTHING AND LET
                                            THE SUBMISSION CONTINUE


FIELDS FOR SHOWING THE REASONING
--------------------------------

  detail.determination    meets | does_not_meet | needs_review

  detail.confidence       High | Medium | Low

  detail.basis            Why the determination landed where it did

  detail.questionFindings[]   One entry per question


Each entry in questionFindings[]:

  questionId        Matches the question id in the payload
  question          The question as it was asked
  answer            What the requester answered
  nonMedNec         false means the answer supports necessity
  category          supports_necessity | insufficient_alone | non_covered |
                    administrative | unclear
  criterionId       Which criterion it rests on
  citation          The source document and section
  evidence          The answer text, quoted verbatim
  reason            Why it supports or does not support necessity
  confidence        High | Medium | Low


FIELDS FOR LOGGING
------------------

  meta    Service and knowledge versions, token counts, timings.
          Not for display.


ON A RECHECK
------------

callType comes back as "reevaluation", and clarifyingQuestion is null.
We do not ask twice.
